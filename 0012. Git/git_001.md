# Git Repository Init, First Commit & Main Branch — Giải thích lý thuyết chi tiết

## 1. Tổng quan: Git lưu trữ cái gì?

Trước khi đi vào lệnh cụ thể, cần hiểu Git lưu trữ dữ liệu như thế nào:

- Git không lưu "sự khác biệt giữa các file" (delta) như SVN. Git lưu **snapshot toàn bộ cây thư mục** tại mỗi lần commit.
- Mỗi đối tượng (blob, tree, commit) được định danh bằng **SHA-1 hash** (40 ký tự hex) → nội dung không đổi thì hash không đổi, nội dung đổi 1 byte thì hash đổi hoàn toàn.
- Git là **distributed**: mỗi clone là một repo đầy đủ với toàn bộ lịch sử.
- Git có **3 vùng chính**: Working Directory → Staging Area (Index) → Repository (.git).

Điều này giải thích tại sao "init" và "first commit" lại quan trọng: đó là lúc bạn tạo ra **cấu trúc đối tượng gốc** mà mọi thứ sau này tham chiếu tới.

## 2. `git init` — Khởi tạo repository

### Lý thuyết

`git init` tạo ra thư mục ẩn `.git/` — đây là **repository thực sự**. Nội dung quan trọng bên trong:

```
.git/
├── HEAD            # con trỏ tới branch hiện tại (vd: ref: refs/heads/main)
├── config          # cấu hình riêng của repo này
├── description     # dùng cho gitweb (thường bỏ trống)
├── hooks/          # script chạy tự động ở các sự kiện (pre-commit, post-merge...)
├── info/exclude    # ignore cục bộ (không commit)
├── objects/        # nơi lưu blob, tree, commit (nội dung thực)
│   ├── info/
│   └── pack/
├── refs/
│   ├── heads/      # các branch (mỗi file = 1 branch, chứa SHA của commit)
│   └── tags/       # các tag
└── index           # staging area (binary)
```

**Điểm mấu chốt:**

1. Trước khi commit đầu tiên, `.git/refs/heads/` **rỗng** — chưa có branch nào tồn tại thực sự. `HEAD` trỏ tới một branch "chưa sinh" (`ref: refs/heads/main`), nhưng file refs/heads/main chưa tồn tại → Git gọi trạng thái này là **unborn branch**.
2. `git init` **không** tạo commit, không tạo branch thực. Nó chỉ tạo "khung xương".
3. Repo đã init nhưng chưa commit → `git branch` sẽ **không liệt kê branch nào** (vì chưa có commit nào để branch trỏ tới).

### Các biến thể

```bash
git init                    # tạo repo trong thư mục hiện tại
git init <tên-thư-mục>      # tạo thư mục mới và init bên trong
git init --bare            # tạo "bare repo" — không có working directory
                           # dùng làm remote/server (vd: trên GitHub, GitLab)
git init --initial-branch=main   # đặt tên branch mặc định ngay khi init
git init -b main                 # viết tắt
```

**Bare repo là gì?** Bare repo không có `.git/` con — toàn bộ thư mục *chính là* `.git`. Nó không có working directory vì không ai "làm việc" trực tiếp trên server. Các remote repo (origin) bản chất là bare repo.

### Cấu hình mặc định khi init

Git đọc `init.defaultBranch` trong config. Nếu không set, Git cũ (≤2.27) dùng `master`, Git mới (≥2.28) cảnh báo và dùng `master` cho tới khi bạn set. Từ Git 2.28+, `init.defaultBranch` có thể set global:

```bash
git config --global init.defaultBranch main
```

Sau đó mọi `git init` mới sẽ dùng `main`.

## 3. Tại sao lại là "main"?

Đây là câu hỏi lý thuyết hay:

- **Lý do kỹ thuật**: Tên branch không có ý nghĩa đặc biệt với Git. `master` chỉ là tên mặc định từ thời Linus Torvalds. Git coi `main`, `master`, `develop` là như nhau — chỉ là con trỏ tới commit.
- **Lý do cộng đồng**: Sau phong trào 2020 (Software Freedom Conservancy, GitHub, GitLab...), nhiều tổ chức chuyển sang `main` vì từ "master/slave" mang hàm ý không phù hợp.
- **Lý do kỹ thuật thực sự**: `main` ngắn gọn, dễ gõ. Nhưng **quan trọng hơn**: tên branch mặc định phải **nhất quán** giữa local và remote, nếu không sẽ sinh ra các vấn đề như "`git push` lần đầu bị từ chối vì remote có `main` còn local có `master`".

Từ góc nhìn Git internals, `HEAD` là con trỏ tới branch hiện tại:
```
HEAD → refs/heads/main → <SHA-1 của commit>
```
Khi branch chưa tồn tại (unborn), `HEAD` vẫn ghi `ref: refs/heads/main` nhưng file ref chưa có. Lần commit đầu tiên sẽ **tạo file** `refs/heads/main` và ghi SHA vào.

## 4. First commit — Cơ chế bên trong

### Luồng dữ liệu

```
Working Tree ──git add──► Staging Area (Index) ──git commit──► Objects + Refs
```

1. **`git add <file>`**:
   - Git tính hash nội dung file (blob SHA-1), nén zlib, ghi vào `.git/objects/xx/yyyy...`
   - Ghi entry vào `.git/index`: (đường dẫn, mode, blob SHA)
   - **Blob đã tồn tại trong objects** — kể cả khi bạn chưa commit! `git add` đã "vật chất hóa" nội dung thành đối tượng Git.

2. **`git commit -m "..."`**:
   - Git đọc toàn bộ index, xây **tree objects** đệ quy (mỗi thư mục = 1 tree, chứa blob và tree con).
   - Tạo **commit object** chứa: tree gốc, author, committer, timestamp, message, và `parent` (với first commit: **không có parent** — đây là root commit).
   - Cập nhật `refs/heads/main` = SHA của commit mới.
   - `HEAD` vẫn trỏ `refs/heads/main`.

3. **First commit đặc biệt**:
   - **Không có parent** → đó là **root commit**. Mọi repo có thể có nhiều root commit (khi merge các lịch sử không liên quan).
   - **Tạo branch thực sự đầu tiên** từ trạng thái "unborn" — từ đây `refs/heads/main` tồn tại, `git branch` bắt đầu hiển thị.
   - Commit này là điểm neo cho toàn bộ DAG (Directed Acyclic Graph) lịch sử sau này.

### Mổ xẻ commit object

Commit object chứa các dòng:

```
tree 4b825dc642cb6eb9a060e54bf8d69288fbee4904
parent <SHA>         ← KHÔNG có ở first commit
author  Name <email> 1700000000 +0700
committer Name <email> 1700000000 +0700

feat: initial commit
```

- `tree`: SHA của tree gốc mô tả snapshot.
- `parent`: SHA của commit cha. Root commit không có dòng này.
- `author` vs `committer`: khác nhau khi rebase/cherry-pick/merge (author giữ nguyên, committer đổi).

## 5. Quy trình chuẩn (best practice)

```bash
# 1. Tạo thư mục & vào trong
mkdir my-project && cd my-project

# 2. Khởi tạo repo với branch mặc định main
git init -b main

# 3. Cấu hình danh tính (nếu chưa set global)
git config user.name "Nguyen Van A"
git config user.email "a@example.com"

# 4. Tạo .gitignore TRƯỚC khi add — tránh add nhầm node_modules, .env, build/
echo "node_modules/" > .gitignore
echo ".env"         >> .gitignore
echo "build/"       >> .gitignore

# 5. Xem trạng thái (file nào untracked)
git status

# 6. Stage toàn bộ file cần thiết
git add .
# hoặc: git add README.md src/ .gitignore

# 7. Kiểm tra lại staging (rất nên làm trước commit đầu)
git status
git diff --cached          # xem nội dung sẽ commit
git ls-files               # liệt kê file trong index

# 8. Commit đầu tiên
git commit -m "chore: initial commit"

# 9. Kiểm tra
git log --oneline --graph
git branch                 # giờ sẽ thấy * main
```

## 6. Các lỗi thường gặp & cách khắc phục

### 6.1 Commit đầu tiên bị sai branch (master thay vì main)

```bash
# Cách 1: đổi tên branch hiện tại
git branch -m master main

# Cách 2: nếu chưa có commit nào (unborn branch)
# → không cần làm gì, chỉ cần set default
git config --global init.defaultBranch main
```

**Lý do**: `git branch -m old new` chỉ đổi tên tham chiếu. Với unborn branch, `git branch` không thấy branch nào nên lệnh này sẽ lỗi → phải commit trước hoặc dùng `git symbolic-ref HEAD refs/heads/main`.

### 6.2 Lỡ add file nhạy cảm (.env, credentials)

```bash
git rm --cached .env          # bỏ khỏi index, GIỮ file trên đĩa
echo ".env" >> .gitignore
git commit --amend -m "chore: initial commit"   # sửa commit đầu
```

**Cảnh báo lý thuyết**: Nếu đã **push** commit đó lên remote, `--amend` sẽ tạo commit mới (SHA mới) và lịch sử diverge. Phải `git push --force` — nguy hiểm nếu người khác đã pull. Với thông tin nhạy cảm đã push, **phải coi như đã lộ**: rotate key ngay, không chỉ xóa file.

### 6.3 Lỡ commit quá nhiều thứ linh tinh

```bash
git reset --soft HEAD~1     # quay về trước commit, giữ mọi thứ trong staging
# hoặc
git reset HEAD~1            # giữ nguyên trong working tree, bỏ staging
# rồi sửa .gitignore, add lại, commit lại
```

**Lý thuyết**: `--soft` chỉ di chuyển con trỏ `HEAD` và `refs/heads/main` về commit cha; index và working tree giữ nguyên. Commit cũ vẫn tồn tại trong objects cho tới khi GC (`git gc` mặc định sau ~30 ngày với reflog).

### 6.4 Đã commit nhưng quên .gitignore từ đầu

Vấn đề: file đã vào index thì `.gitignore` **không có tác dụng** (ignore chỉ áp dụng với untracked file). Phải:

```bash
git rm --cached <file-hoặc-thư-mục>
echo "<pattern>" >> .gitignore
git add .gitignore
git commit -m "chore: ignore build artifacts"
```

## 7. So sánh `git init` vs `git clone`

|                 | `git init`                         | `git clone`                           |
| --------------- | ---------------------------------- | ------------------------------------- |
| Tạo `.git/`     | ✅                                  | ✅ (tự động)                           |
| Có commit nào   | ❌ (unborn branch)                  | ✅ (toàn bộ lịch sử + refs)            |
| Remote origin   | Không (phải `git remote add`)      | Có sẵn (trừ `--bare`/`--no-checkout`) |
| Working tree    | Rỗng (hoặc có sẵn file bạn tự tạo) | Checkout sẵn branch mặc định          |
| Trường hợp dùng | Dự án mới, chưa có trên server     | Dự án đã có remote                    |

Lý thuyết: `git clone` thực chất là `git init` + `git remote add origin` + `git fetch` + `git checkout`. Nó copy **toàn bộ objects** (không phải chỉ snapshot mới nhất).

## 8. Liên hệ với remote — Push lần đầu

Sau first commit, khi push lần đầu:

```bash
git remote add origin git@github.com:user/repo.git
git push -u origin main
```

**Lý thuyết `-u` (--set-upstream)**: Liên kết branch local `main` với branch remote `origin/main`. Sau đó `git push` / `git pull` không cần tham số. Cụ thể Git ghi vào `.git/config`:

```
[branch "main"]
    remote = origin
    merge = refs/heads/main
```

**Vấn đề hay gặp**: Remote tạo sẵn branch `main` (trên GitHub) nhưng local là `master` → push bị reject vì "non-fast-forward" (lịch sử không liên quan). Giải pháp: đổi tên local (mục 6.1) hoặc `git push -u origin master:main` (push branch local lên tên remote khác).

**Lý thuyết non-fast-forward**: Git từ chối push nếu commit đích không phải con cháu (descendant) của commit đích hiện tại trên remote. Vì local và remote có root commit khác nhau → không có quan hệ ancestor → bắt buộc force push hoặc đồng bộ lại.

## 9. Tóm tắt lý thuyết cốt lõi

| Khái niệm          | Định nghĩa                           | Lưu ý                               |
| ------------------ | ------------------------------------ | ----------------------------------- |
| `git init`         | Tạo `.git/`, chưa có commit          | Trạng thái unborn branch            |
| First commit       | Tạo **root commit** (không parent)   | Vật chất hóa branch đầu tiên        |
| `HEAD`             | Con trỏ tới branch hiện tại          | Symbolic ref, không phải branch     |
| Branch             | File trong `refs/heads/` chứa SHA    | Chỉ là con trỏ, không "chứa" commit |
| Commit             | Object bất biến, hash SHA-1          | Snapshot, không phải delta          |
| `main` vs `master` | Tên do cấu hình `init.defaultBranch` | Không có ý nghĩa đặc biệt với Git   |
| Staging area       | `.git/index` — binary                | `git add` đã tạo blob ngay          |
| Bare repo          | Không working dir                    | Dùng làm remote                     |

**Điểm mấu chốt cần nhớ**: Git là **content-addressable filesystem**. Mọi thứ (file, thư mục, commit) là đối tượng bất biến được đặt tên bằng hash nội dung. Branch chỉ là con trỏ nhẹ (41 byte trong file) tới các commit. `git init` tạo khung, first commit tạo root, từ đó bạn xây DAG lịch sử bằng `git commit` (thêm nút) và `git merge`/`git rebase` (sắp xếp lại DAG, thực chất là tạo commit mới).
