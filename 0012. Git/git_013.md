# Git Stash — Giải thích lý thuyết chi tiết

---

## 1. Bản chất: `git stash` thực sự làm gì?

### 1.1 Định nghĩa cốt lõi

**`git stash`** là lệnh **tạm cất** các thay đổi chưa commit (cả staged và unstaged) vào một **ngăn xếp ẩn (stash stack)**, đưa Working Directory và Index về trạng thái **sạch** (khớp với HEAD). Sau đó, bạn có thể **lấy lại** các thay đổi đó bất cứ lúc nào.

> **Điểm lý thuyết quan trọng nhất**: `git stash` **không xóa** thay đổi — nó **di chuyển** chúng vào một nơi khác (stash stack). Đây là "ngăn kéo tạm" cho công việc đang dang dở.

### 1.2 Tại sao cần `stash`?

Có nhiều tình huống **bắt buộc** Working Tree phải sạch:

| Tình huống                | Lý do cần sạch                                |
| ------------------------- | --------------------------------------------- |
| `git switch <branch>`     | Không thể đổi branch nếu có thay đổi conflict |
| `git pull` (merge/rebase) | Merge sẽ ghi đè file có thay đổi              |
| `git rebase`              | Rebase cần working tree sạch để replay commit |
| `git merge`               | Tương tự pull                                 |
| `git cherry-pick`         | Cần working tree sạch                         |

**Giải pháp truyền thống**: commit tạm ("wip"). **Nhược điểm**: làm bẩn lịch sử, phải dọn dẹp sau.

**Giải pháp `stash`**: cất tạm mà **không tạo commit trong lịch sử branch**. Đây là lý do `stash` tồn tại.

### 1.3 Cơ chế bên trong — Stash là gì?

Đây là phần **lý thuyết sâu nhất** — và cũng là phần ít người hiểu.

**Stash thực chất là một commit object đặc biệt**, không thuộc branch nào, chỉ được tham chiếu bởi `refs/stash`.

Khi bạn `git stash`, Git tạo **hai hoặc ba commit ẩn**:

```
                    ┌─────────────────┐
                    │  stash commit   │  ← W (merge commit)
                    │  (refs/stash)   │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
       ┌──────────┐   ┌──────────┐   ┌──────────┐
       │  HEAD    │   │  Index   │   │ Untracked│  ← (nếu có --include-untracked)
       │  (I)     │   │  (S)     │   │  (U)     │
       └──────────┘   └──────────┘   └──────────┘
```

Cấu trúc chi tiết:

```
Commit W (stash chính — merge commit):
  parent 1: I (commit HEAD lúc stash — "Index commit")
  parent 2: S (commit chứa trạng thái của Index — "Stash commit")
  parent 3: U (commit chứa untracked files — CHỈ khi --include-untracked)

Commit I (Index commit):
  tree = working tree tại thời điểm stash
  parent = HEAD

Commit S (Stash commit):
  tree = index tại thời điểm stash
  parent = I

Commit U (Untracked commit):
  tree = untracked files
  parent = HEAD (không phải W)
```

**Điểm mấu chốt**:
- Stash là **một commit có 2-3 parent** — không thuộc branch nào.
- Nó được tham chiếu bởi **`refs/stash`** (một ref đặc biệt).
- **Stack** là danh sách các stash commit nối tiếp: `stash@{0}`, `stash@{1}`, ...
- Đây là lý do `stash` **không bị mất** cho tới khi `gc` dọn (nếu unreachable) hoặc `stash drop`.

### 1.4 Ref `refs/stash` — "ngăn xếp"

```bash
cat .git/refs/stash
# SHA của stash gần nhất

git reflog stash
# Danh sách mọi stash (giống reflog của HEAD)
```

**Lý thuyết**: Stash stack **chính là reflog của `refs/stash`**. Mỗi lần stash, `refs/stash` được cập nhật và một entry mới được thêm vào reflog của nó. Đây là lý do:
- `stash@{0}` = stash gần nhất.
- `stash@{1}` = stash trước đó.
- ...
- Có thể truy cập từng stash qua `stash@{N}`.

## 2. Cú pháp và các dạng

### 2.1 Cú pháp cơ bản

```bash
git stash                       # tương đương: git stash push
git stash push                  # cất thay đổi (tracked, không untracked)
git stash push -m "message"     # có message (khuyến nghị)
git stash push -u               # bao gồm untracked files
git stash push -a               # bao gồm cả ignored files
git stash push -p               # interactive: chọn từng hunk
git stash push <path>           # chỉ stash file cụ thể
```

### 2.2 `push` vs `save` (legacy)

- `git stash save "message"` — **cũ**, deprecated (từ Git 2.16+).
- `git stash push -m "message"` — **mới**, khuyến nghị.

`save` vẫn hoạt động nhưng **không hỗ trợ pathspec** và các option mới. Luôn dùng `push`.

## 3. Các option của `push` — Chi tiết lý thuyết

### 3.1 Không có option — Chỉ stash tracked

```bash
git stash
```

**Hành động**:
- Cất mọi thay đổi của **tracked files** (cả staged và unstaged).
- **KHÔNG** cất untracked files (file mới hoàn toàn).
- **KHÔNG** cất ignored files.

**Kết quả**:
- Working Tree = HEAD (sạch, trừ untracked).
- Index = HEAD (sạch).

**Ví dụ**:

```bash
# Trước
git status
# Changes to be committed:
#   modified:   file1.js        (staged)
# Changes not staged for commit:
#   modified:   file2.js        (unstaged)
# Untracked files:
#   newfile.js                  (untracked)

git stash

# Sau
git status
# Untracked files:
#   newfile.js                  ← VẪN CÒN
# (file1.js, file2.js về HEAD)
```

### 3.2 `-u` / `--include-untracked`

```bash
git stash push -u
```

**Hành động**: Cất **cả untracked files** (file chưa từng được Git biết).

**Lý thuyết**: Untracked files được lưu trong **commit parent thứ 3** (`U`) của stash commit. Khi pop/apply, chúng được khôi phục vào working tree.

**Cẩn thận**: `-u` có thể stash nhiều file rác (build output, `.DS_Store` nếu chưa ignore). Kiểm tra `.gitignore` trước.

### 3.3 `-a` / `--all`

```bash
git stash push -a
```

**Hành động**: Cất **tất cả** — tracked + untracked + **ignored files**.

**Lý thuyết**: `-a` bao gồm cả file trong `.gitignore`. Đây là lý do `-a` **hiếm dùng** — thường bạn không muốn stash `node_modules/`, `.env`, build output...

**Ứng dụng**: Khi cần "reset hoàn toàn" môi trường làm việc, kể cả ignored files.

### 3.4 `-p` / `--patch` — Interactive

```bash
git stash push -p
```

**Hành động**: Mở chế độ interactive — hiển thị **từng hunk** của thay đổi, hỏi bạn có muốn stash hunk đó không.

```
diff --git a/file.js b/file.js
@@ -1,3 +1,3 @@
 function foo() {
-  return 1;
+  return 2;
 }
Stash this hunk [y,n,q,a,d,s,e,?]?
```

**Lý thuyết**: `-p` cho phép **stash một phần** của thay đổi — cực hữu ích khi muốn tách công việc: phần này stash, phần kia giữ lại.

**Các lựa chọn**:
- `y`: stash hunk này.
- `n`: không stash.
- `q`: dừng, không stash gì thêm.
- `a`: stash tất cả hunk còn lại.
- `d`: không stash hunk này và các hunk còn lại.
- `s`: tách hunk thành phần nhỏ hơn.
- `e`: sửa hunk thủ công.

### 3.5 `-m` / `--message` — Đặt tên

```bash
git stash push -m "wip: login form"
```
