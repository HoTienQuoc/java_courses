Việc hoàn tác (undoing) trong Git và việc sử dụng trình soạn thảo Vi là hai kỹ năng nền tảng nhưng thường gây khó khăn cho người mới. Bài viết này sẽ giải thích chi tiết cơ chế lý thuyết đằng sau các lệnh hoàn tác của Git và cách vận hành của Vi.

## 🌀 PHẦN A — GIT UNDOING THINGS: NGHỆ THUẬT HOÀN TÁC

Git cung cấp nhiều công cụ để "hoàn tác", nhưng mỗi công cụ giải quyết một vấn đề khác nhau. Chìa khóa để hiểu chúng là mô hình **"ba cây" (three trees)** của Git: **Working Directory** (thư mục làm việc), **Index/Staging Area** (vùng tạm) và **Commit History** (lịch sử commit, được trỏ tới bởi `HEAD`).

### 1. `git restore` — "Cây đũa thần" cho Working Directory và Index

`git restore` là lệnh hiện đại, chuyên biệt cho việc hoàn tác ở cấp độ file, được tách ra từ `git checkout` để tránh nhầm lẫn.

*   **Hủy bỏ thay đổi chưa stage trong Working Directory:**
    ```bash
    git restore <file>
    ```
    Lệnh này lấy nội dung của file từ commit gần nhất (HEAD) và ghi đè lên những thay đổi bạn đang có trong working directory. **Đây là hành động không thể hoàn tác** đối với các thay đổi chưa được stage, vì chúng chưa từng được Git lưu lại.

*   **Bỏ stage (unstage) một file:**
    ```bash
    git restore --staged <file>
    ```
    Lệnh này chỉ di chuyển file ra khỏi Index, đưa nó về trạng thái "chưa stage". Các thay đổi của bạn trong working directory vẫn được giữ nguyên vẹn.

### 2. `git reset` — "Cỗ máy thời gian" di chuyển con trỏ branch

`git reset` là một lệnh mạnh mẽ, có thể di chuyển con trỏ của branch hiện tại (`HEAD`) về một commit trước đó, về cơ bản là "viết lại lịch sử" của nhánh đó. Sức mạnh của nó nằm ở các flag, quyết định mức độ "hoàn tác" ảnh hưởng đến ba cây như thế nào.

| Flag                     | Hành động trên `HEAD`  | Hành động trên Index   | Hành động trên Working Directory | Kết quả                                                                                                                                    |
| :----------------------- | :--------------------- | :--------------------- | :------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **`--soft`**             | Di chuyển về commit cũ | **Không đổi**          | **Không đổi**                    | Các commit bị "hủy" vẫn còn nguyên trong Index (đang stage).                                                                               |
| **`--mixed`** (mặc định) | Di chuyển về commit cũ | **Reset về commit cũ** | **Không đổi**                    | Các thay đổi của commit bị hủy được đưa ra khỏi Index, trở thành unstaged nhưng vẫn còn trên đĩa.                                          |
| **`--hard`**             | Di chuyển về commit cũ | **Reset về commit cũ** | **Reset về commit cũ**           | **Nguy hiểm nhất**: Xóa bỏ mọi thay đổi trong cả Index và Working Directory. Chỉ flag này mới thực sự "xóa" công việc chưa commit của bạn. |

**Ví dụ điển hình:** `git reset --soft HEAD~1` sẽ hủy commit gần nhất nhưng giữ lại tất cả thay đổi của nó trong khu vực stage, sẵn sàng cho bạn commit lại với một message khác.

> **Cảnh báo:** `git reset` viết lại lịch sử. Chỉ nên dùng nó trên các commit **chưa được push** lên remote. Nếu bạn đã chia sẻ lịch sử đó, việc reset sẽ gây rắc rối cho những người khác.

### 3. `git revert` — "Liều thuốc giải" an toàn cho lịch sử công khai

`git revert` được thiết kế để hoàn tác các commit **đã được chia sẻ công khai**. Thay vì xóa bỏ quá khứ, nó tạo ra một **commit mới** có nội dung **đảo ngược hoàn toàn** với commit mà bạn muốn hủy bỏ.

*   **Cơ chế:** Nếu commit `A` thêm một dòng, commit `revert A` sẽ xóa dòng đó đi. Lịch sử không bị viết lại; cả commit gốc và commit đảo ngược đều tồn tại, minh bạch cho tất cả mọi người.
*   **Ưu điểm:** An toàn cho làm việc nhóm vì không ai bị buộc phải "đồng bộ hóa" lại lịch sử đã thay đổi.
*   **Hạn chế:** `git revert` chỉ hoạt động ở cấp độ commit, không thể revert một file đơn lẻ.

### 4. Các công cụ hoàn tác khác

*   **`git commit --amend`:** Sửa đổi commit **gần nhất**. Bạn có thể thêm các thay đổi đã stage vào commit đó hoặc chỉ sửa lại message commit. Lệnh này thực chất là tạo ra một commit mới thay thế commit cũ, nên cũng **viết lại lịch sử** và cần thận trọng nếu commit đó đã được push.
*   **`git clean`:** Xóa các file **chưa được theo dõi (untracked)** khỏi working directory. Đây là lệnh duy nhất trong số này có thể "dọn dẹp" các file không nằm trong sự quản lý của Git.
    *   `git clean -n`: Chạy thử (dry-run) để xem những gì sẽ bị xóa.
    *   `git clean -fd`: Thực sự xóa các file và thư mục untracked. **Hãy luôn dùng `-n` trước** vì hành động này là vĩnh viễn.

### 5. "Phao cứu sinh" — `git reflog`

Nếu bạn lỡ tay chạy `git reset --hard` và mất đi các commit quan trọng, `git reflog` là công cụ giải cứu. Reflog ghi lại **mọi sự di chuyển của `HEAD`**, kể cả những commit không còn được tham chiếu bởi bất kỳ branch nào. Bạn có thể tìm lại SHA của commit đã mất trong reflog và quay trở lại bằng `git reset --hard <SHA>`.

> **Lưu ý quan trọng:** Reflog chỉ cứu được các **commit**. Nó **không thể** phục hồi các thay đổi trong working directory chưa từng được commit hoặc stage. Do đó, nguyên tắc vàng là: **commit thường xuyên**.

## ✍️ PHẦN B — VI TEXT EDITOR: TRIẾT LÝ CỦA SỰ TỐI GIẢN

Vi (và Vim) là một trình soạn thảo văn bản theo chế độ (**modal editor**). Điều này có nghĩa là ý nghĩa của các phím bấm thay đổi hoàn toàn tùy thuộc vào **chế độ (mode)** hiện tại của trình soạn thảo.

### 1. Ba chế độ cốt lõi của Vi

1.  **Command Mode (Chế độ Lệnh):** Đây là chế độ mặc định khi bạn mở Vi. Trong chế độ này, các phím được dùng để ra lệnh như di chuyển con trỏ, xóa, copy, paste... thay vì gõ văn bản.

2.  **Insert Mode (Chế độ Chèn):** Đây là chế độ bạn thực sự gõ văn bản. Mọi phím bấm đều được hiểu là ký tự để chèn vào file.

3.  **Last Line Mode (Chế độ Dòng cuối):** Đây là một chế độ đặc biệt, được kích hoạt bằng cách gõ dấu hai chấm (`:`) từ Command Mode. Nó cho phép bạn nhập các lệnh mở rộng như lưu file, thoát, tìm kiếm, thay thế... trên một dòng ở cuối màn hình.

### 2. Cách chuyển đổi giữa các chế độ

*   **Từ Command Mode sang Insert Mode:** Nhấn `i` (chèn trước con trỏ), `a` (chèn sau con trỏ), `o` (mở dòng mới bên dưới).
*   **Từ Insert Mode trở về Command Mode:** Nhấn phím `Esc`.
*   **Từ Command Mode sang Last Line Mode:** Nhấn phím `:`.
*   **Từ Last Line Mode trở về Command Mode:** Nhấn `Esc` hoặc sau khi chạy xong một lệnh.

### 3. Các lệnh sinh tồn cơ bản

#### Trong Command Mode (điều hướng và thao tác)

| Lệnh            | Chức năng                                  |
| :-------------- | :----------------------------------------- |
| `h` `j` `k` `l` | Di chuyển con trỏ: trái, xuống, lên, phải. |
| `x`             | Xóa ký tự dưới con trỏ.                    |
| `dd`            | Xóa toàn bộ dòng hiện tại.                 |
| `yy`            | Copy (yank) toàn bộ dòng hiện tại.         |
| `p`             | Paste nội dung vừa copy/xóa sau con trỏ.   |
| `u`             | Hoàn tác (undo) thao tác gần nhất.         |
| `/pattern`      | Tìm kiếm "pattern" trong file.             |

#### Trong Last Line Mode (lưu và thoát)

| Lệnh  | Chức năng                                     |
| :---- | :-------------------------------------------- |
| `:w`  | Ghi lại file (save).                          |
| `:q`  | Thoát khỏi Vi.                                |
| `:wq` | Ghi lại và thoát.                             |
| `:q!` | Thoát **mà không ghi lại** (bỏ mọi thay đổi). |

## 💎 TỔNG KẾT

*   **Git Undoing:** Việc chọn đúng công cụ hoàn tác phụ thuộc vào việc bạn muốn thay đổi cây nào và commit đó đã được chia sẻ hay chưa. Hãy nhớ: `restore` cho working tree, `reset` cho lịch sử cục bộ (nguy hiểm), `revert` cho lịch sử công khai (an toàn), và `reflog` là phao cứu sinh cuối cùng.
*   **Vi Editor:** Sức mạnh của Vi đến từ triết lý "modal". Việc làm quen với việc chuyển đổi giữa các chế độ và sử dụng các tổ hợp phím trong Command Mode sẽ giúp bạn thao tác văn bản nhanh và hiệu quả hơn nhiều so với các trình soạn thảo thông thường.

Nếu bạn muốn đi sâu hơn vào một lệnh cụ thể nào (ví dụ: các tùy chọn nâng cao của `git reset` hay các lệnh di chuyển phức tạp trong Vi), hãy cho tôi biết nhé.
