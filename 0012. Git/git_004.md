# Git Remote Repositories — Giải thích lý thuyết chi tiết

---

## 1. Bản chất: Remote là gì trong mô hình phân tán?

### 1.1 Định nghĩa cốt lõi

Remote repository (kho lưu trữ từ xa) là **một bản sao đầy đủ khác của repo** — không phải "server trung tâm" theo nghĩa client-server. Git là **distributed (phân tán)**: mỗi clone là một repo hoàn chỉnh với toàn bộ lịch sử. Remote chỉ là **một cái tên (alias) trỏ tới một URL** — nơi Git biết phải fetch/push tới.

> **Điểm lý thuyết quan trọng nhất**: Remote **không phải là một khái niệm lưu trữ**. Nó là **cấu hình** — một dòng trong `.git/config` ánh xạ tên → URL → tập refspec. Không có "trạng thái remote" nào được lưu; mọi thứ bạn "biết" về remote chỉ là **bản sao cache** của lần fetch gần nhất, nằm trong **remote-tracking branches** (`refs/remotes/`).

### 1.2 Nội bộ: Remote lưu ở đâu?

```bash
cat .git/config
```

```ini
[remote "origin"]
    url = git@github.com:user/repo.git
    fetch = +refs/heads/*:refs/remotes/origin/*
    pushurl = git@github.com:user/repo.git       # optional
```

Ba thành phần cốt lõi:

| Thành phần | Ý nghĩa                                                 |
| ---------- | ------------------------------------------------------- |
| `url`      | Địa chỉ fetch (đọc)                                     |
| `pushurl`  | Địa chỉ push (ghi) — mặc định dùng `url` nếu không có   |
| `fetch`    | **Refspec** — mapping giữa ref phía remote và ref local |

**Đây là toàn bộ "định nghĩa" của một remote.** Không có gì khác. Mọi lệnh `git fetch/push/pull` đọc cấu hình này và thực thi refspec.

## 2. Remote-tracking branches — Trái tim của mô hình

### 2.1 Phân biệt ba loại branch

Đây là phần **hay bị hiểu sai nhất** trong Git:

| Loại                                      | Nơi lưu          | Ai di chuyển                  | Ví dụ                      |
| ----------------------------------------- | ---------------- | ----------------------------- | -------------------------- |
| **Local branch**                          | `refs/heads/`    | Bạn (commit, reset, merge...) | `refs/heads/main`          |
| **Remote-tracking branch**                | `refs/remotes/`  | Git (khi fetch/push)          | `refs/remotes/origin/main` |
| **Remote's branch** (thực sự trên server) | Repo phía server | Người khác hoặc bạn khi push  | —                          |

### 2.2 Lý thuyết: Remote-tracking branch KHÔNG phải là remote

`origin/main` (đọc là "origin slash main") là **con trỏ local** — một **snapshot** của `main` trên origin **tại lần fetch/push gần nhất**. Nó **không tự cập nhật**; nó chỉ cập nhật khi bạn chủ động `git fetch` hoặc `git push`.

Điều này giải thích tại sao:

- Nếu đồng nghiệp push commit mới lên `origin`, `origin/main` local **vẫn trỏ commit cũ** cho tới khi bạn `git fetch`.
- `git status` có thể báo "Your branch is up to date with 'origin/main'" — nhưng đó là **so với snapshot cũ**, không phải trạng thái server thực tế. Git không liên lạc với server khi chạy `status` (trừ khi bạn cấu hình đặc biệt).

### 2.3 Đồ thị refs sau `git fetch`

Trước fetch:
```
refs/heads/main           → A
refs/remotes/origin/main  → A     (snapshot cũ)
```

Server có thêm commit `B` (do người khác push). Sau `git fetch`:
```
refs/heads/main           → A     (KHÔNG đổi)
refs/remotes/origin/main  → B     (cập nhật)
```

**Kết luận lý thuyết**: `git fetch` chỉ **cập nhật remote-tracking branches** và **objects** — nó **không chạm vào branch local**, **không chạm vào working tree**. Đây là lý do `fetch` an toàn tuyệt đối (không thể mất việc).

### 2.4 `git pull` = `fetch` + `merge`/`rebase`

```bash
git pull
# tương đương:
git fetch
git merge origin/main          # hoặc rebase nếu pull.rebase=true
```

`pull` **có thể gây conflict** vì nó merge/rebase. `fetch` thì không bao giờ.

**Cấu hình liên quan**:
```ini
[pull]
    rebase = true              # hoặc "merges", "false" (mặc định merge)
    ff = only                  # chỉ fast-forward, fail nếu không được
```

## 3. Refspec — Ngôn ngữ ánh xạ ref

### 3.1 Cú pháp

```
[+]<src>:<dst>
```

- `+`: cho phép **non-fast-forward update** (ghi đè mù quáng). Thiếu `+` → Git từ chối cập nhật nếu không phải fast-forward.
- `<src>`: ref phía nguồn (remote khi fetch; local khi push).
- `<dst>`: ref phía đích (local khi fetch; remote khi push).
- Có thể dùng wildcard `*`.

### 3.2 Refspec mặc định

```
+refs/heads/*:refs/remotes/origin/*
```

→ Mọi branch trên remote (`refs/heads/*`) được fetch về **local dưới tên `refs/remotes/origin/*`**. Đây là lý do `origin/main`, `origin/feature-x`, `origin/release-1.0` xuất hiện trong `git branch -r`.

### 3.3 Các dạng refspec quan trọng

```bash
# Chỉ fetch 1 branch cụ thể
git fetch origin main                              # shorthand cho main:refs/remotes/origin/main? Không — xem dưới
git fetch origin refs/heads/main:refs/remotes/origin/main
git fetch origin main:refs/remotes/origin/main     # dạng ngắn

# Fetch vào branch local (hiếm dùng)
git fetch origin main:my-temp-branch               # tạo/sửa my-temp-branch local = main remote

# Fetch KHÔNG cập nhật remote-tracking (chỉ tải objects)
git fetch origin main --no-tags                   # vẫn cập nhật origin/main
```

**Lưu ý tinh tế**: `git fetch origin main` (không có `:`) fetch branch `main` theo refspec cấu hình — nó cập nhật `refs/remotes/origin/main` nếu có refspec khớp. Không phải "chỉ tải objects".

### 3.4 Push refspec — Ngược chiều

```bash
git push origin main                    # main local → main remote
git push origin main:prod               # main local → prod trên remote
git push origin main:                      # main local → main remote (dạng ngắn)
git push origin :feature                  # XÓA feature trên remote
git push origin --delete feature          # Cùng tác dụng
git push origin HEAD:refs/heads/new-branch    # An toàn hơn — ghi rõ
git push origin HEAD                       # Push commit hiện tại lên branch cùng tên
```

**`git push origin :feature`** là cú pháp "xóa" — **refspec rỗng ở src** nghĩa là "push nothingness", tức xóa `<dst>`.

### 3.5 Lý thuyết non-fast-forward

Khi push, Git kiểm tra: **commit đích trên remote có phải là tổ tiên (ancestor) của commit mới không?**

```
Remote: A → B → C
Local:  A → B → C → D        ✅ fast-forward, OK
```

```
Remote: A → B → C → E
Local:  A → B → C → D        ❌ non-FF (D không có E trong ancestor)
```

Trường hợp non-FF xảy ra khi: người khác đã push, bạn rebase/amend, hoặc lịch sử phân kỳ. Git **từ chối push** để tránh mất commit của người khác.

## 4. Các lệnh quản lý remote

### 4.1 `git remote` — Thao tác cơ bản

```bash
git remote                        # liệt kê tên
git remote -v                     # kèm URL (fetch + push)
git remote show origin            # thông tin chi tiết (cần network)
git remote add <name> <url>       # thêm
git remote remove <name>          # xóa (còn: rm)
git remote rename <old> <new>     # đổi tên
git remote set-url <name> <url>
git remote set-url --push <name> <url>     # chỉ đổi pushurl
git remote set-head <name> -a     # cập nhật refs/remotes/<name>/HEAD
git remote prune <name>           # xóa remote-tracking branch đã biến mất
```

### 4.2 `git remote show origin` — Bức ảnh toàn cảnh

```bash
git remote show origin
```

Output:
```
* remote origin
  Fetch URL: git@github.com:user/repo.git
  Push  URL: git@github.com:user/repo.git
  HEAD branch: main
  Remote branches:
    main           tracked
    feature/login  tracked
    old-experiment stale (use 'git remote prune' to remove)
  Local branch configured for 'git pull':
    main merges with remote main
  Local ref configured for 'git push':
    main pushes to main (up to date)
```

Đây là **lệnh duy nhất** trong số các lệnh remote **liên lạc với server** (khác với `git remote -v` chỉ đọc config). Nó cho biết:
- Branch local nào track branch remote nào.
- Branch remote nào **stale** (đã bị xóa trên server nhưng còn trong snapshot local).
- Cấu hình pull/push cho từng branch.

### 4.3 `git branch -vv` — Xem tracking relationship

```bash
git branch -vv
```

```
* main    a1b2c3d [origin/main: ahead 2, behind 1] feat: something
  feature e4f5g6h [origin/feature: gone]              fix: bug
  local    i7j8k9l                                     chore: init
```

Cột trong `[...]`:
- `[origin/main: ahead 2, behind 1]`: local có 2 commit chưa push, remote có 1 commit chưa fetch.
- `[origin/feature: gone]`: upstream branch đã bị xóa trên server — cần `git fetch --prune`.
- `local` không có ngoặc: **không có upstream** (không track remote nào).

## 5. Upstream tracking — Liên kết branch local ↔ remote

### 5.1 Upstream là gì?

Khi bạn `git push -u origin main`, Git ghi vào `.git/config`:

```ini
[branch "main"]
    remote = origin
    merge = refs/heads/main
```

Đây là **upstream configuration** — nó cho Git biết:
- `git push` (không tham số) → đẩy lên `origin/main`.
- `git pull` (không tham số) → fetch từ `origin` và merge/rebase `origin/main`.
- `git status` → hiển thị ahead/behind so với `origin/main`.

### 5.2 Thiết lập upstream

```bash
git push -u origin main                          # lần push đầu
git branch --set-upstream-to=origin/main main    # sau khi đã có remote-tracking
git branch -u origin/main                        # shorthand (đang ở branch main)
git branch --unset-upstream                      # gỡ bỏ
```

### 5.3 Lý thuyết `push.default` — Hành vi push không tham số

Cấu hình `push.default` quyết định `git push` làm gì khi không có tham số:

| Giá trị                      | Hành vi                                                                   |
| ---------------------------- | ------------------------------------------------------------------------- |
| `simple` (mặc định Git ≥2.0) | Push branch hiện tại lên upstream cùng tên. Fail nếu tên khác.            |
| `upstream`                   | Push lên upstream (kể cả tên khác).                                       |
| `current`                    | Push branch hiện tại lên branch **cùng tên** trên remote.                 |
| `matching`                   | Push mọi branch local **có branch cùng tên** trên remote (nguy hiểm, cũ). |
| `nothing`                    | Fail nếu không có refspec rõ ràng.                                        |

`simple` an toàn nhất: bảo vệ khỏi push nhầm branch lên sai chỗ.

## 6. Các tình huống nâng cao

### 6.1 Nhiều remote — Workflow "fork"

Khi bạn fork repo trên GitHub:

```bash
git clone git@github.com:you/project.git           # origin = fork của bạn
cd project
git remote add upstream git@github.com:org/project.git   # upstream = repo gốc
```

Refs sau khi fetch cả hai:

```
refs/remotes/origin/*      # fork của bạn (bạn có quyền push)
refs/remotes/upstream/*    # repo gốc (chỉ fetch)
```

Cập nhật fork:
```bash
git fetch upstream
git checkout main
git merge upstream/main      # hoặc rebase
git push origin main         # đẩy lên fork
```

**Lưu ý lý thuyết**: `upstream` ở đây là **tên remote do người dùng tự đặt** — không có gì đặc biệt. Có thể đặt là `source`, `orig`, gì cũng được. Ngược lại, **upstream tracking** (mục 5) là khái niệm khác — nó là "branch nào local track branch nào remote".

### 6.2 `git fetch --all` và `--prune`

```bash
git fetch --all                # fetch từ MỌI remote đã cấu hình
git fetch --all --prune        # fetch + xóa remote-tracking branch đã mất trên server
git config --global fetch.prune true    # bật prune mặc định
```

**Tại sao cần prune?** Khi ai đó xóa branch `feature` trên server, `origin/feature` local **vẫn tồn tại** (Git không tự xóa khi fetch). `--prune` bảo fetch: "sau khi cập nhật, xóa các remote-tracking branch không còn tương ứng trên server".

### 6.3 `--force-with-lease` — Push an toàn hơn `--force`

```bash
git push --force                   # GHI ĐÈ mù quáng
git push --force-with-lease        # GHI ĐÈ chỉ khi remote chưa đổi từ lần fetch cuối
git push --force-with-lease=main:abc123    # Rõ ràng: chỉ nếu remote main vẫn ở abc123
```

**Lý thuyết**:
- `--force` gửi thẳng lên server, ghi đè bất kể ai đã push gì trong lúc bạn chuẩn bị.
- `--force-with-lease` kiểm tra: **remote ref hiện tại có khớp với remote-tracking branch local không?** Nếu ai đó đã push từ lần fetch cuối → ref khác → **từ chối**, bảo vệ commit của họ.

`--force-with-lease` là **lựa chọn đúng** trong hầu hết trường hợp (sau rebase, amend). Chỉ dùng `--force` khi bạn chắc chắn muốn xóa mọi commit người khác vừa push.

### 6.4 `git push --dry-run`

```bash
git push --dry-run
```

Mô phỏng push mà không thực sự gửi — cho biết cái gì sẽ được đẩy, cái gì bị từ chối. **Luôn chạy trước `--force`**.

### 6.5 `git remote prune` vs `git fetch --prune`

- `git fetch --prune`: fetch + prune trong một lệnh (khuyến nghị).
- `git remote prune origin`: **chỉ** prune (không fetch objects). Hữu ích khi muốn dọn dẹp nhanh.

### 6.6 `git ls-remote` — "Nhìn trộm" server không cần fetch

```bash
git ls-remote origin
```

Output:
```
a1b2c3d...	HEAD
a1b2c3d...	refs/heads/main
e4f5g6h...	refs/heads/feature
i7j8k9l...	refs/tags/v1.0.0
```

Đọc **trực tiếp** refs từ server mà **không** tải objects, **không** cập nhật remote-tracking. Cực hữu ích để kiểm tra trạng thái thực của server (khắc phục điểm yếu "snapshot cũ" của remote-tracking branch).

### 6.7 Partial clone và shallow clone

```bash
git clone --depth=1 <url>          # shallow: chỉ commit mới nhất
git clone --filter=blob:none <url> # partial: bỏ qua blobs, tải khi cần (lazy)
git clone --single-branch -b main <url>   # chỉ 1 branch
```

**Lý thuyết**: `--depth` cắt DAG thành "gốc giả" (grafted commit) — repo không có tổ tiên đầy đủ. `--filter` giữ DAG đầy đủ nhưng **trì hoãn tải objects** — Git tải khi cần (promisor remote). Hữu ích cho CI/CD, monorepo lớn.

## 7. Đồng bộ lịch sử phân kỳ — Các chiến lược

Khi local và remote đã phân kỳ (`ahead N, behind M`):

### 7.1 Merge (an toàn, giữ lịch sử)

```bash
git fetch origin
git merge origin/main
```

Tạo merge commit (hoặc fast-forward nếu có thể). Lịch sử **không viết lại**, an toàn cho team.

### 7.2 Rebase (sạch, viết lại local)

```bash
git fetch origin
git rebase origin/main
```

Áp lại commit local lên đầu `origin/main`. Lịch sử **tuyến tính**, nhưng **viết lại SHA** của commit local → cần `push --force-with-lease`. **Quy tắc vàng**: chỉ rebase commit **chưa push** (hoặc branch cá nhân).

### 7.3 Pull với chiến lược cụ thể

```bash
git pull --rebase                  # fetch + rebase
git pull --no-rebase               # fetch + merge (mặc định cũ)
git pull --ff-only                 # fail nếu không fast-forward — an toàn nhất
```

`--ff-only` đảm bảo **không tạo merge commit bất ngờ** và **không rebase ngầm** — chỉ chấp nhận khi local là ancestor của remote. Rất tốt cho branch chính.

## 8. Troubleshooting thường gặp

### 8.1 "rejected: non-fast-forward"

```bash
# Nguyên nhân: ai đó đã push trước
git fetch origin
git log HEAD..origin/main          # xem commit mới
git merge origin/main              # hoặc rebase
git push
```

### 8.2 "fatal: refusing to merge unrelated histories"

Xảy ra khi hai repo có **root commit khác nhau** (vd: repo local init + repo GitHub có README). Giải pháp:

```bash
git pull origin main --allow-unrelated-histories
```

**Lý thuyết**: Git từ chối vì không thể xác định "tổ tiên chung" — merge sẽ tạo commit cha kép nhưng DAG không liên thông. `--allow-unrelated-histories` chấp nhận rủi ro (có thể conflict nặng), thường dùng khi hợp nhất hai lịch sử độc lập có chủ đích.

### 8.3 "error: src refspec main does not match any"

Nguyên nhân: branch `main` **không tồn tại** ở local (có thể bạn chưa commit, hoặc tên là `master`). Kiểm tra:

```bash
git branch                        # chỉ thấy branch hiện có
git log --oneline                 # có commit chưa?
```

### 8.4 "fatal: 'origin' does not appear to be a git repository"

- Chưa `git remote add origin`.
- URL sai.
- SSH key chưa cấu hình (nếu dùng `git@`).

Debug:
```bash
git remote -v                     # xem URL
ssh -T git@github.com             # test SSH
git ls-remote origin              # test toàn bộ kết nối
```

### 8.5 "Authentication failed" với HTTPS

GitHub bỏ mật khẩu từ 2021 → phải dùng **Personal Access Token (PAT)** hoặc SSH. Chuyển sang SSH:

```bash
git remote set-url origin git@github.com:user/repo.git
```

### 8.6 Đã push branch sai, cần xóa trên remote

```bash
git push origin --delete wrong-branch
```

Không ảnh hưởng tới branch local hay objects — chỉ xóa **con trỏ ref** trên remote.

## 9. Tổng kết lý thuyết

| Khái niệm                             | Định nghĩa cốt lõi                               | Lưu ý                                          |
| ------------------------------------- | ------------------------------------------------ | ---------------------------------------------- |
| **Remote**                            | Alias (tên) → URL + refspec, trong `.git/config` | Không lưu trữ gì — chỉ là cấu hình             |
| **Remote-tracking branch**            | `refs/remotes/<remote>/*` — snapshot cache       | **Không tự cập nhật**, không phải server thực  |
| **Refspec**                           | `[+]<src>:<dst>` — ánh xạ ref                    | `+` = cho phép non-FF                          |
| **Fetch**                             | Tải objects + cập nhật remote-tracking           | **Không** đụng branch local, an toàn tuyệt đối |
| **Pull**                              | `fetch` + `merge`/`rebase`                       | Có thể conflict                                |
| **Push**                              | Đẩy commit + di chuyển ref trên remote           | Kiểm tra non-FF; `--force-with-lease` an toàn  |
| **Upstream**                          | `branch.<name>.remote` + `.merge`                | Quyết định `push`/`pull` không tham số         |
| **Prune**                             | Xóa remote-tracking branch đã mất trên server    | `fetch --prune` khuyến nghị                    |
| **`--force` vs `--force-with-lease`** | Ghi đè mù vs kiểm tra lease                      | Luôn ưu tiên `--force-with-lease`              |
| **`push.default`**                    | Hành vi push không tham số                       | `simple` là default an toàn                    |

**Điểm mấu chốt cần nhớ**: Remote là **một cái tên trong config**, không phải thực thể lưu trữ. Mọi thứ bạn "biết" về remote là **snapshot cũ** trong `refs/remotes/` — cập nhật chỉ khi fetch/push. `fetch` chỉ cập nhật snapshot (an toàn), `pull` mới merge/rebase (rủi ro). Khi push bị từ chối, đó là **cơ chế bảo vệ** — đừng dùng `--force` trừ khi bạn đã `fetch` và hiểu rõ mình đang ghi đè cái gì; hãy dùng `--force-with-lease` để tự động phát hiện nếu có ai vừa push.
